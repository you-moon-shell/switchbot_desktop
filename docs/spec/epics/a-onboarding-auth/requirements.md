## 1. 概要・目的

SwitchBot公式クラウドAPI v1.1 を利用するための **API資格情報（Token / Secret）** を、ユーザーから安全に受け取り・検証・保管し、次回以降は自動で再利用する。資格情報の取り扱いはアプリ全体のセキュリティの根幹であり、**機密はRustコアとOSキーチェーンの外に出さない**ことを最優先とする。

## 2. スコープ

**含む（In Scope）**
- 初回起動時のオンボーディング（Token/Secret 入力）
- 入力資格情報の疎通検証（署名付きリクエスト）
- OSキーチェーンへの保存と、次回起動時の自動ロード
- 資格情報の更新・削除（ログアウト）
- 運用中のトークン失効（401/403）検知と再認証導線

**含まない（Out of Scope）**
- 複数アカウント／複数トークンの切替（**単一アカウント前提**）
- 取得手順の画像・SwitchBotアプリへのディープリンク（テキスト案内のみ）
- デバイス操作・センサー可視化・自動化・常駐挙動（Epic B〜F）

## 3. ユーザーストーリー

- **US-A1**: 新規ユーザーとして、SwitchBotの Token / Secret を入力し、デバイスにアクセスできるようにしたい。
- **US-A2**: ユーザーとして、資格情報を安全に記憶してほしい（毎回入力したくない）。
- **US-A3**: ユーザーとして、入力が誤っていたら明確に分かるようにしたい。
- **US-A4**: ユーザーとして、資格情報を更新・削除できるようにしたい。
- **US-A5**: ユーザーとして、トークンが無効になったら再認証を促してほしい。

## 4. 機能要件（EARS）

### A1. 初回判定
- **WHEN** アプリ起動時 **GIVEN** キーチェーンに資格情報が無い **THEN** オンボーディング画面を表示する。

### A2. 取得方法の案内
- **WHILE** オンボーディング画面にいる間 **THE SYSTEM SHALL** Token/Secret の取得手順（SwitchBotアプリ → プロフィール → 設定 → 開発者向けオプション）を簡易テキストで案内する。

### A3. 入力と疎通検証
- **WHEN** ユーザーが Token と Secret を入力し「接続」を実行 **THEN** 署名付きで `GET /v1.1/devices` を呼び検証する。
- **WHEN** 検証成功（HTTP 200 かつ レスポンス `statusCode: 100`）**THEN** 資格情報をOSキーチェーンに保存 **AND** メイン画面へ遷移する。
- **WHEN** 検証失敗（HTTP 401 など未認可）**THEN** エラー理由を表示 **AND** 資格情報を保存しない **AND** 入力画面に留まる。

### A4. 保存と秘匿（最重要）
- **THE SYSTEM SHALL** Token/Secret を OSキーチェーン（macOS Keychain / Windows Credential Manager）にのみ保存する。
- **THE SYSTEM SHALL** Token/Secret を WebView・ログ・SQLite・設定ファイルに一切書き出さない。

### A5. 次回以降の自動ロード
- **WHERE** 資格情報 **IS** キーチェーンに存在 **THE SYSTEM SHALL** 起動時に自動ロードし、オンボーディングを省略してメイン画面へ進む。

### A6. 資格情報の管理
- **WHEN** ユーザーが設定から「資格情報を更新」 **THEN** 再入力・再検証し、成功時のみ上書き保存する。
- **WHEN** ユーザーが「ログアウト（資格情報を削除）」 **THEN** キーチェーンから削除 **AND** オンボーディング画面に戻す。

### A7. 運用中のトークン失効
- **WHEN** 通常運用中にAPIが 401/403 を返す **THEN** 資格情報が無効と判断 **AND** 再認証を促す **AND** 背景処理（ポーリング/自動化）を一時停止する。

## 5. 非機能要件 / セキュリティ

- **NFR-A1**: HMAC署名・HTTP送信・キーチェーン操作はすべて Rustコア内で行い、WebViewには公開しない。
- **NFR-A2**: 署名用タイムスタンプ `t` はシステム時計（ミリ秒）を使用。`nonce` はリクエスト毎にユニーク（UUID）。
- **NFR-A3**: ログ出力時は Token/Secret をマスキングし、平文を残さない。
- **NFR-A4**: フロントとコアの通信は `invoke`/`listen` のみ。フロントは SwitchBot API を直接呼ばない。

> 署名アルゴリズムの具体（`HMAC-SHA256(secret, token + t + nonce)` を Base64 化等）は実装で確定済み（[backend §6.3](../../architecture/backend.md)）。本ドキュメントは「署名付きで検証・通信する」ことを要件として規定するに留める。

## 6. エッジケース

- 入力値の前後空白を除去し、空入力はバリデーションで弾く。
- ネットワーク不通時の検証は「資格情報の正否は不明（ネットワークエラー）」として **401 と区別**して表示し、保存しない。
- 端末時計が大きくずれると署名が拒否される → 検証失敗時に「時計ずれの可能性」を案内する。
- キーチェーンへのアクセスがOSに拒否された場合はエラー表示し、再試行可能にする。

## 7. 受け入れ基準（テスト可能）

- [ ] **AC-1**: 正しい Token/Secret で接続するとデバイス一覧が取得でき、再起動後は再入力が不要。
- [ ] **AC-2**: 誤った Secret で接続すると明確なエラーが表示され、資格情報が保存されない。
- [ ] **AC-3**: 資格情報はOSキーチェーンにのみ保存され、設定ファイル・DB・ログに平文が残らない。
- [ ] **AC-4**: 運用中に 401 を受け取ると再認証導線が表示され、背景処理が停止する。
- [ ] **AC-5**: ネットワーク不通時の検証失敗は 401（認証エラー）と区別して表示される。

## 8. 前提・制約

- 単一アカウント前提（複数トークン切替は対象外）。
- ログアウト/削除機能は Epic A に含む。
- 取得手順の案内はテキストのみ（画像・ディープリンクは将来拡張）。

## 9. 用語

| 用語 | 意味 |
|---|---|
| Token | SwitchBotアプリの開発者向けオプションで発行されるAPIトークン。リクエストの `Authorization` ヘッダに使用 |
| Secret | 同上で発行される署名鍵。HMAC-SHA256 署名の鍵として使用（送信はしない） |
| sign | リクエストごとに生成する署名（`t`・`nonce` と組で送る） |
| キーチェーン | OS提供の機密保管庫（macOS Keychain / Windows Credential Manager） |
