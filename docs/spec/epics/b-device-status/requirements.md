## 1. 概要・目的

認証済みの資格情報を使い、SwitchBot クラウド API から **デバイス一覧と現在の状態を取得して表示する（読み取り専用）**。操作（コマンド送信）は含めず、まず「自分のデバイスが見える」状態を**最小リスク**で作る。書き込み副作用が無いため、認証基盤（Epic A）の上で安全に積める最初の機能。

## 2. スコープ

**含む（In Scope）**
- デバイス一覧の取得・表示（物理デバイス）
- 各デバイスの現在状態の取得・表示
- **状態の定期自動更新（ポーリング・アクティブ表示中のみ）** ＋ 手動更新
- 取得失敗時のエラー表示（401/403 の再認証導線・ネットワーク不通・レート制限を区別）

**含まない（Out of Scope）**
- デバイスへのコマンド送信・シーン実行（Epic C / D / E）
- 赤外線リモコン（`infraredRemoteList`）— 状態を持たないため。一覧・操作は後続エピックで扱う
- 状態履歴の保存・グラフ可視化（**Backlog: 可視化**）。本エピックの自動更新は「最新状態の表示」のみで、履歴は残さない
- グルーピング／並び替え／お気に入り等の整理機能

## 3. ユーザーストーリー

- **US-B1**: ユーザーとして、登録済みの SwitchBot デバイス一覧を見たい。
- **US-B2**: ユーザーとして、各デバイスの現在状態（電源 on/off、温湿度、バッテリー等）を確認したい。
- **US-B3**: ユーザーとして、最新状態に手動で更新したい。
- **US-B4**: ユーザーとして、取得に失敗したら理由（再認証が必要／通信不可／制限超過）が分かるようにしたい。
- **US-B5**: ユーザーとして、画面を開いている間は状態が自動で最新化されてほしい（毎回手で更新したくない）。

## 4. 機能要件（EARS）

### B1. 一覧取得
- **WHEN** メイン画面を開いた、または一覧を更新した **THEN** 署名付きで `GET /v1.1/devices` を呼び、物理デバイス一覧（`deviceId` / `deviceName` / `deviceType` / Hub 配下か）を取得して表示する。

### B2. 状態取得
- **WHEN** ユーザーがデバイスを選択した、または状態を更新した **THEN** `GET /v1.1/devices/{deviceId}/status` を呼び、**種別に応じた現在状態**を表示する。

### B3. 手動更新
- **WHILE** デバイス画面にいる間 **THE SYSTEM SHALL** ユーザー操作で一覧／状態を再取得できる手段（更新ボタン等）を提供する。

### B4. 取得失敗の区別
- **WHEN** API が 401/403 を返す **THEN** 資格情報が無効と判断し、再認証導線へ誘導する（Epic A の A7 と整合）。
- **WHEN** ネットワーク不通 **THEN** 「通信できません（正否不明）」として 401 と区別して表示する。
- **WHEN** 429（レート制限）**THEN** 「API の制限に達しました」と表示し、時間をおく案内をする。

### B5. 自動更新（ポーリング）
- **WHILE** デバイス画面がアクティブ（表示中）の間 **THE SYSTEM SHALL** 一定間隔で状態を自動取得し、表示を最新化する。
- **WHERE** 画面が非アクティブ（最小化／非表示／バックグラウンド）の間 **THE SYSTEM SHALL** ポーリングを停止する（バックグラウンドでは取得しない）。
- **WHEN** 再びアクティブになった **THEN** 直ちに 1 回取得して最新化し、定期取得を再開する。

### B6. レート制限の遵守
- **THE SYSTEM SHALL** ポーリングの間隔・対象を制御し、SwitchBot の上限（約 1万コール/日）を超えない。状態取得は**単一の取得経路に集約**して重複させない。
- **NOTE**: `status` はデバイス単位の取得のため「台数 × 頻度」がコール数になる。既定間隔と対象（全デバイス／表示中のみ 等）は実装しながら調整する（既定値はコードで持つ）。

## 5. 非機能要件 / セキュリティ

- **NFR-B1**: 署名・HTTP 通信は Rust コア内のみ（NFR-A1 踏襲）。フロントへは**状態データ（非機密）のみ**渡し、Token/Secret は渡さない。
- **NFR-B2**: 自動更新は `invoke` の定期再取得で実現する（フロントのクエリ層で間隔を制御）。Rust 常駐ポーラー＋`listen` イベントは、自動化等で取得を共有したくなった時に Backlog から昇格する（B 単独では不要）。
- **NFR-B3**: 取得した状態は**永続化しない**（履歴保存は Backlog）。メモリ上／Query キャッシュのみで保持。
- **NFR-B4**: ドメインモデル（`models::Device`）はフロントへ生で返さず、commands 層の Serialize 可能な DTO に翻訳する（backend §12 の方針）。

## 6. エッジケース

- デバイス 0 件 → 空状態を表示（「デバイスがありません」）。
- 状態取得に未対応／想定外のデバイス種別 → 取得できたフィールドのみ表示し、未知種別でもクラッシュしない（フォールバック表示）。
- 一覧は取れたが特定デバイスの `status` 取得が失敗 → そのデバイスのみエラー表示し、他は表示を継続する。
- Hub を介さない等で `status` が限定的なケース → 取れる範囲で表示する。
- 端末時計が大きくずれて署名が拒否される → 取得失敗として「時計ずれの可能性」を案内（Epic A エッジと整合）。
- 台数が多い／間隔が短いと 1万/日 に近づく → 間隔を延ばす・対象を表示中に限る等で抑制（既定値は実装時に決める）。

## 7. 受け入れ基準（テスト可能）

- [ ] **AC-B1**: 認証済みで開くと、自分の物理デバイス一覧が表示される。
- [ ] **AC-B2**: デバイスを選ぶ／更新すると、現在状態（種別に応じた項目）が表示される。
- [ ] **AC-B3**: 手動更新で最新が反映される。
- [ ] **AC-B4**: 401/403 → 再認証導線、ネットワーク不通／429 はそれぞれ区別して表示される。
- [ ] **AC-B5**: デバイス 0 件・`status` 取得に失敗したデバイスが混在しても画面が壊れない。
- [ ] **AC-B6**: 画面アクティブ中は状態が一定間隔で自動更新され、取得は単一経路に集約されている（同一データの重複取得が無い）。
- [ ] **AC-B7**: 非アクティブ時はポーリングが停止し（バックグラウンドで API を叩かない）、再アクティブで再開＋即時取得する。

## 8. 前提・制約

- Epic A（認証）完了が前提。資格情報は keychain から取得する。
- 単一アカウント前提。
- 取得対象は物理デバイス。赤外線リモコンと操作系は後続エピック。

## 9. 用語

| 用語 | 意味 |
|---|---|
| `deviceId` | デバイス固有 ID。`status` / `commands` のパスに使う |
| `deviceType` | デバイス種別（Bot / Meter / Plug 等）。状態の項目が種別で変わる |
| `status` | `GET /devices/{id}/status` が返す現在状態（種別別フィールド） |
| `infraredRemoteList` | 赤外線リモコン登録一覧（本エピック対象外） |
